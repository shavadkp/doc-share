# Architecture Note

## Overview

The application follows a simple client-server architecture.

### Frontend

React + TypeScript application responsible for:

* Authentication
* Dashboard UI
* Rich text editing
* Upload workflow
* Sharing workflow

### Backend

Django REST Framework API responsible for:

* Authentication
* Document CRUD operations
* File upload processing
* Document sharing
* Persistence

### Database

SQLite is used for persistence.

Tables include:

* User
* Document
* SharedDocument

---

## Design Decisions

### Rich Text Storage

Document content is stored as JSON generated by Tiptap.

Benefits:

* Preserves formatting
* Easy to render and update
* Simple persistence model

### Authentication

Token Authentication was chosen because:

* Easy to implement
* Suitable for assignment scope
* Works well with SPA frontends

### File Upload

Limited to:

* .txt
* .md

This kept implementation focused and reduced parsing complexity.

### Sharing

A SharedDocument model stores relationships between documents and users.

This provides:

* Clear ownership
* Simple sharing workflow
* Future extensibility for permissions

---

## Tradeoffs

Not implemented:

* Real-time collaboration
* Version history
* Comments
* Role-based permissions

These were intentionally deprioritized to focus on core document workflows.
